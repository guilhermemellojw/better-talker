## O que corrige

### Placeholder duplicado na Biblioteca

- O sync cria um anexo `missing` no segundo aparelho (só metadados, sem
  binário). O import deduplicava apenas por `sha256`; como o placeholder
  antigo não tinha hash, o arquivo importado virava uma segunda linha. A
  mesma publicação aparecia em “Disponíveis” e em “Precisa de atenção”.
- **P0 — lista:** `attentionAttachments` esconde `missing`/`failed` já
  resolvidos por `sha256`, pela publicação (mesmo tipo) ou pelo nome
  normalizado. Nada é apagado; o placeholder volta a aparecer se o anexo
  pronto for removido. Chaves amplas de revista (`w`, `wp`, `g`, `gn`) não
  contam como prova de mesma publicação; edições específicas (`w17.10`)
  continuam contando.
- **P1 — import:** o import reutiliza um `missing`/`failed` sem arquivo
  válido (mesmo nome ou mesma publicação + tipo), preservando id e vínculo
  com a nota, em vez de criar outro anexo.
- **P2 — sync:** o manifesto de attachments envia e lê `sha256`; o segundo
  aparelho preenche o placeholder por conteúdo. Backfill de docs antigos só
  quando o campo está ausente; hash remoto divergente não é sobrescrito.
