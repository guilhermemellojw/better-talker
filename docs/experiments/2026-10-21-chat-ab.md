# A/B — Chat do Copilot vs DeepSeek Web (2026-10-21)

Objetivo: descobrir por que o chat do Copilot não produz uma resposta tão boa
quanto a do DeepSeek Web, e transformar o achado em fix permanente.

Método: **matriz controlada de chamadas**, não impressão subjective. O system
prompt **real** do app foi capturado no dispositivo (A34, nota "Ter esperança…"),
e as mesmas chamadas foram feitas contra `https://api.deepseek.com/v1` com a
chave do próprio app. Isso isola prompt × provider sem depender de-browser.

> Dados brutos (prompt capturado, conversas do Web, respostas da matriz) ficam
> **fora do repo** em `/tmp/opencode/ab/` — contêm conteúdo do usuário e não
> devem ser publicados. Este documento traz só métricas agregadas.

## 5. Conclusão por hipótese

| Hipótese | Veredito | Evidência |
|---|---|---|
| **H1 dossiê sempre** | **fraca** | G1×G2 (196→174) e S0×S1: só muda o tamanho. Mantido o gate (dossiê só quando a pergunta cita ref/seção) — encolhe o prompt sem custo |
| **H2 regra de card** | **refutada** | o prompt do Web também manda usar `<texto-do-card>`; S2 muda pouco. Mantido como está |
| **H3 temperature 0,2** | **não confirmada** | P5 (0,2) × P10 (0,7): 392 × 343 palavras. O calor do Web vem do prompt, não da temperatura. Mantido 0,2 |
| **H4 histórico por seção** | **secundária** | não testada no provider (o Web também é conversacional). Sem ação |
| **H5 mentor hint** | **fraca** | S3 ≈ S0. O modo mentor é funcionalidade, não defeito. Mantido |
| **H6 modelo** | **não era a causa** | `deepseek-v4-pro` é **mais lento** (9–17 s) e não evita o corte. Mantido `deepseek-flash` |
| **H7 persona fragmentada** | **parcial** | o Web é um prompt só; a fragmentação custa a preservação de termos ("Deus" × "Jeová"). Adicionada a regra de preservação |
| **H8 Web Search/DeepThink (nova)** | **real, mas não replicável** | o Web buscou a w25.07 e estatísticas de terceiros; o app tem acervo local. Não é bug do prompt — é diferença de ferramenta |
| **H9 orçamento de saída (nova)** | **CAUSA DOMINANTE** | P1 37 chars × P2 1964 chars, mesmo prompt e mesmo modelo |
| **H10 reasoning × max_tokens (nova)** | **CAUSA DOMINANTE** | `low`@1000 → 984 tokens de reasoning e 37 chars de resposta; `none`@1000 → 1964 chars, 3 s mais rápido |

### Achado adicional (fora do escopo do prompt): extração das publicações

O acervo local **tem** a w25.07, mas o app entrega ao modelo o **título** do
parágrafo em vez do texto (`w25.07 pág. 22 §8-9` → "Em que armadilha Baruque
caiu De acordo com 1 Coríntios 4:6…"), e as "FONTES DE CONTEÚDO" apontam para
índices que não são parágrafos (`§424`, `§536`). O Web, com Search, leu o
artigo e citou os §§ reais. **Enquanto a extração do `.jwpub` não for
corrigida, o app não consegue fundamentar como o Web.**

## 6. Fix implementado (`fix/chat-quality`, a partir da `main`)

| Mudança | Arquivo | Efeito medido |
|---|---|---|
| Chat livre sem thinking (`reasoning_effort=none`); "Profundo" mantém `high` | `DeepSeekProvider.reasoningEffortFor` | 37 → 1964 chars no mesmo orçamento |
| Teto do "Profundo" 2000 → **4096** | `DeepSeekProvider.DEEP_OUTPUT_TOKENS` | `high`@2000 ainda dava vazio; @4096 fecha com `stop` |
| Orçamento do chat 1000 → **2048** (4096 com fontes resolvidas) | `LlmProvider`, `answerOutputBudget` | cabe uma introdução de discurso (~1300 palavras) |
| Dossiê só quando a pergunta cita ref/seção/publicação | `DossierGate.kt` + VM | prompt menor em pergunta genérica, sem perda na pergunta de conteúdo |
| Persona preserva termos bíblicos ("Jeová", "Escrituras") | `ChatPromptBuilder` | elimina a troca "Jeová" → "Deus" |

Validação no A34 (nota de teste, fix compilado e instalado): resposta **completa
(982 chars, card íntegro) em 2,8 s** — antes o mesmo chat devolvia fragmento de
37 chars ou "Não consegui gerar a resposta agora".

Matriz pós-fix (mesmo prompt real do app): **2194 chars, 395 palavras, card
completo, 7× "Jeová", 0× "Deus", 5,5 s.**

Testes: 2152 verdes (inclui `DossierGateTest`, `AnswerBudgetTest`,
`BudgetEffortTest`, `ChatPersonaTest`).

## 7. O que ficou de fora (e por quê)

- **Web Search no app** (H8): exige tool-calling no provider + política de
  fontes. É projeto, não flag.
- **Extração do `.jwpub`** (achado adicional): é a causa do gap de
  fundamentação — precisa de parser dos parágrafos.
- **Temperature/modelo/histórico**: sem evidência de ganho.
